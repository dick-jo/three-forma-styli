# Verified implementation state — 2026-07-22

This is the current handoff after the cleanup, Figma merge, typography build, and
Scatter source-of-truth reconstruction. The previous day's audit remains as a
historical record; its proposed typography architecture has now been replaced by
the explicit model described in [typography-foundation.md](./typography-foundation.md).

## Product boundary

TFS remains an asynchronous, build-time system generator. Authors provide a small,
typed set of design decisions; TFS validates and expands those decisions into
portable CSS, TypeScript, font assets, manifests, specimens, DTCG, and Figma output.
It is not a runtime theme engine and it does not own framework components.

Its useful distinction from general token transformers is derivation with strong
constraints and sensible defaults. The resolved output remains explicit and
inspectable; helpers never silently remap unsupported font capabilities.

## Typography and font pipeline

- Permanent atomic `--fs-*` primitives remain mode-aware.
- Semantic roles and their variant names are entirely author-defined. Core contains
  no built-in `prose`, `heading`, `label`, `min`, `m`, or weight-ramp vocabulary.
- Each complete recipe resolves family, size, weight, line height, letter spacing,
  style, features, and variation settings. Weight is visible and editable in the
  specimen rather than hidden at role level.
- Normal and italic are first-class where prepared font capabilities support them;
  unsupported style/weight combinations fail the build. Oblique is supported by the
  data model but is never synthesized or invented.
- Font preparation reads real capabilities, converts configured inputs to WOFF2,
  writes `@font-face`, and emits factual manifests. Exact source/copy/URL syntax is
  project-configurable.
- Metric-adjusted generic fallbacks are generated for normal and italic faces.
  There is deliberately no approval/candidate lifecycle in TFS: review evidence
  belongs to the consuming project or its CI, not to token generation state.
- Helper CSS uses ordinary classes by default and kebab-case selectors. Zero
  specificity `:where(...)` output is an explicit opt-in. Global CSS and CSS Module
  targets are both available.
- The interactive specimen supports per-recipe reset, double-click slider reset,
  primary/fallback comparison, stable line diagnostics, actual width delta and
  line-count reporting, style/weight combinations, and a local `tfs specimen serve`
  review command.

## Project build and portability

`tfs build` is the single orchestration command. A project config can emit a
portable output directory containing tokens, typed system data, prepared fonts,
font manifests, typography helpers, a TypeScript typography contract, a specimen,
and Figma/DTCG artifacts. CSS selector attributes for color, size, and time modes
are first-class project configuration rather than CLI-only defaults.

`system.generated.ts` preserves authored system inputs, resolved token values,
mode keys, and arbitrary author metadata. This provides a build-time contract for
applications that need the same canonical native-theme values without hand-copying
them into application source.

The clean `/Users/dickjones/project-local/tfs-scatter` project proves the complete
portable workflow with committed font inputs, one canonical `src/system.ts`,
reproducible generated output, and an exact production-token reconciliation check.
Generated files remain disposable and ignored; the source project is authoritative.

## Deliberately deferred—not hidden

- Scatter application rollout, `<Text />`, component migration, preload placement,
  and removal of legacy font declarations belong to a separate consumer session.
- Scatter's final line-height, tracking, and role-weight values are authored visual
  decisions. TFS supplies diagnostics and an editor but does not pretend font metrics
  can infer product taste.
- DTCG/Figma serializers are still color-focused. Expanding official token types is
  useful future work, not a typography prerequisite.
- Live Figma API validation still requires an eligible real file.
- Publishing a new npm version remains a deliberate release task after the Scatter
  canary, not an automatic consequence of this merge.

## Remaining architectural watchpoints

- The legacy IR still keys override token blocks by mode name. TFS now fails loudly
  if a color override and size override share a name; a future major IR revision can
  represent category and name structurally instead.
- Time “modes” remain parallel prefixed root token families, unlike selectable color
  and size modes. Their current behavior is documented, but their terminology merits
  a later focused design decision.
- Destructive Figma reconciliation remains explicit and opt-in; current sync does not
  silently delete remote variables or modes.
- Releases still need versioning, changelog, canary installation, and provenance
  discipline before a 1.0 claim.
